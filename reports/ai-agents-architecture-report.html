关键发现: Arclayer 的分层架构为 AI 集成提供了良好的扩展基础。 插件系统、事件总线、后台任务队列均可直接作为 AI 功能的接入点。 主要缺失的是 AI 业务逻辑层（LLM 调用、Embedding 生成、Prompt 管理、Agent 编排）。

3. Agents 实现分析

3.1 概念区分

项目中存在两类 "Agent" 概念，需严格区分：

A. 开发辅助 Agent（已实现）

Claude Code 等 AI 编程工具的 Agent 配置。位于 .agents/ 目录， 用于辅助开发者进行代码审查、代码探索、重构等任务。面向开发者，非产品功能。

B. 产品内 AI Agent（不存在）

面向用户的 AI Agent 功能——如内容生成 Agent、数据分析 Agent、自动化工作流 Agent。 完全未实现。无 Agent 运行时、工具调用、多步推理等任何产品级 Agent 代码。

3.2 开发辅助 Agent 详解（.agents/ 目录）

技能组技能数用途技术栈

4. AI 架构集成点分析

基于现有架构，以下是 AI 功能的自然集成位置：

4.1 插件系统 (pluggy)

最自然的 AI 集成入口。可实现为独立 arclayer-ai 包， 通过 entry point 发现机制自动加载。利用 ServiceRegistry、 ProviderRegistry、MiddlewareRegistry 注册 AI 服务。

关键文件: apps/api/src/core/plugin/specs.py (hook 定义), apps/api/src/core/plugin/manager.py (注册管理)

4.2 事件总线 (Event Bus)

订阅领域事件触发 AI 处理。如 content.created → 自动生成摘要/标签/翻译， asset.uploaded → AI 图片分析/alt text 生成。

关键文件: apps/api/src/core/events.py

4.3 后台任务 (Taskiq)

重量级 AI 处理（LLM 调用、Embedding 生成、批量分析）作为异步后台任务执行， 遵循现有 assets_thumbnails.py 和 scheduled_publish.py 的模式。

关键文件: apps/api/src/platform/jobs/

4.4 新 API 模块

最常规的方式：创建 src/modules/ai/ 模块，遵循 router → service → repository → schema 模式。 在 core/routes.py 注册路由。

关键文件: apps/api/src/core/routes.py, apps/api/src/modules/
