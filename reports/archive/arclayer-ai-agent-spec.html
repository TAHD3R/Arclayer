架构决策记录

#决策点选择核心理由替代方案
1 Extensions 架构模式 Strapi/Directus 路线 保留 pluggy 类型化 Hook 骨架，补齐消费端、元信息清单、数据库激活、Admin 插槽 WordPress 全局字符串 pub-sub（太松散，不适配多租户 API-first 系统）
2 AI 代码组织 src/llm/ + src/modules/agents/ 分离 API 无关的 LLM 基础能力与 API 层 Agent 逻辑 全部放 src/modules/ai/（耦合度过高）
3 AI 部署模型 Phase 1 内置模块 → 后续 Extensions 化 快速验证核心链路，成熟后解耦为独立 Extension 直接做独立 Extension（初期迭代慢）；独立微服务（运维成本高）
4 LLM API Key 管理 平台共享 Key + 用户/工作空间独立 Key 默认低成本（共享），高级用户灵活（自带 Key） 仅共享 Key（无灵活性）；仅独立 Key（管理复杂）
5 Agent 工具系统 MCP 格式描述 + PydanticAI 执行 MCP 保证工具可跨 Agent 框架复用；PydanticAI 保证类型安全和可测试性 纯 PydanticAI 装饰器（绑定框架）；纯 MCP（缺少类型安全）
6 LLM 网关 LiteLLM Proxy (sidecar) 100+ Provider 统一代理、虚拟 Key 体系、多租户预算、速率限制 自建 Provider 抽象层（重复造轮子）；Portkey（核心功能云锁定）
7 Agent 框架 PydanticAI + LangGraph(按需) 单任务用 PydanticAI（类型安全+FastAPI 天然整合），多步用 LangGraph（有向图+Checkpoint） LangChain（过重）；CrewAI（生态小）；自建 ReAct（需更多维护）
8 RAG 管线 LlamaIndex + pgvector 原生 pgvector 集成、混合搜索、CMS 内容建模天然匹配 LangChain RetrievalQA（代码量大 30-40%）
9 可观测性 Langfuse（按需引入） 初期用 LiteLLM 内置 spend tracking；需要深度调试时引入 Langfuse LangSmith（非 MIT）；自建追踪（开发成本高）

1. Extensions 系统

1.1 概述与边界

设计目标构建 CMS 级别、多租户感知、支持安装/激活/配置/卸载的 Extensions 系统。参照 Strapi 和 Directus 的成熟模式，在现有 pluggy 类型化 Hook 骨架之上补齐消费端、元信息清单、数据库驱动激活、Admin UI 扩展插槽、依赖管理、分发机制。
与现有 pluggy 的关系保留 specs.py 的 Hook 定义和 registries/ 的子注册表。新建 src/core/extensions/ 作为 Extension 系统的统一入口，将原有 core/plugin/ 中的功能逐步整合。两套代码短期内共存，新功能优先走 extensions/。
核心新增(1) Extension Manifest 元信息清单 (2) 加固版生命周期状态机 (3) 数据库驱动激活状态 (4) 依赖解析与加载排序 (5) 消费端 Registry 绑定 (6) Admin UI 扩展插槽 (7) 分发机制 (8) 安全沙箱

1.3 生命周期状态机

将现有 6 阶段（DISCOVER→LOAD→REGISTER→BOOTSTRAP→READY→DESTROY）扩展为 10 阶段，增加安装/激活/停用/卸载，并强制校验阶段顺序。

完整状态转移

                    ┌─────────────────────────────┐
                    │         ABSENT              │ (文件不存在于系统)
                    └──────────┬──────────────────┘
                               │ install()
                               ↓
                    ┌─────────────────────────────┐
                    │        INSTALLED            │ (文件存在，manifest 已验证)
                    └──────────┬──────────────────┘
                               │ activate()      ←── 可配置 per-Workspace
                               ↓
                    ┌─────────────────────────────┐
                    │        ACTIVATED            │ (将在下次启动时加载)
                    └──────────┬──────────────────┘
                               │ 应用启动 → load()
                               ↓
                    ┌─────────────────────────────┐
                    │        REGISTERED           │ (Hook: arclayer_register 已调用)
                    └──────────┬──────────────────┘
                               │ bootstrap()
                               ↓
                    ┌─────────────────────────────┐
                    │        BOOTSTRAPPED         │ (Hook: arclayer_bootstrap 已调用)
                    └──────────┬──────────────────┘
                               │ ready()
                               ↓
                    ┌─────────────────────────────┐
                    │          READY              │ (正常服务中)
                    └──────┬───────────┬──────────┘
                           │          │ deactivate()
                           │          ↓
                           │  ┌───────────────────┐
                           │  │    DEACTIVATED    │ (下次启动不加载)
                           │  └────────┬──────────┘
                           │          │ uninstall()
                           │          ↓
                           │  ┌───────────────────┐
                           │  │     UNINSTALLED   │ → ABSENT
                           │  └───────────────────┘
                           │
                    shutdown│
                           ↓
                    ┌─────────────────────────────┐
                    │        DESTROYED            │ (正常关闭)
                    └─────────────────────────────┘

强制顺序校验

class ExtensionLifecycle:
    """加固版状态机：强制校验阶段转移合法性"""

    _VALID_TRANSITIONS = {
        Phase.ABSENT:      {Phase.INSTALLED},
        Phase.INSTALLED:   {Phase.ACTIVATED, Phase.UNINSTALLED},
        Phase.ACTIVATED:   {Phase.REGISTERED, Phase.DEACTIVATED},
        Phase.REGISTERED:  {Phase.BOOTSTRAPPED},
        Phase.BOOTSTRAPPED:{Phase.READY},
        Phase.READY:       {Phase.DESTROYED, Phase.DEACTIVATED},
        Phase.DEACTIVATED: {Phase.ACTIVATED, Phase.UNINSTALLED},
        Phase.UNINSTALLED: {Phase.ABSENT},
        Phase.DESTROYED:   set(),
    }

    def transition(self, to_phase: Phase) -> None:
        if to_phase not in self._VALID_TRANSITIONS.get(self._phase, set()):
            raise IllegalTransitionError(
                f"Cannot transition from {self._phase} to {to_phase}"
            )
        self._phase = to_phase

1.4 数据库驱动激活状态

参照 WordPress Multisite 的"共享代码 + 每站点独立激活"模式。Extension 代码在文件系统（或 npm 包），激活状态存储在数据库，不同 Workspace 可独立启用/禁用/配置 Extension。

激活流程

应用启动
  │
  ├─→ 1. 扫描已安装 Extension（文件系统 → extensions 表）
  │
  ├─→ 2. 查询当前 Workspace 的激活列表（workspace_extensions 表）
  │     ├─ 平台级强制 Extension（is_required = true）→ 始终加载
  │     ├─ Workspace 主动激活的 Extension → 加载
  │     └─ 未激活的 Extension → 跳过
  │
  ├─→ 3. 依赖拓扑排序（DAG）
  │     ├─ Extension A requires Extension B → B 先加载
  │     └─ 循环依赖检测 → 报错并跳过
  │
  └─→ 4. 按序加载 Extensions
        ├─ instantiate → register → bootstrap → ready
        └─ 失败隔离：单个 Extension 加载失败不影响其他

1.5 Registry & Consumer Binding

现有 registries/ 的 10 个子注册表是"只写"的——Extension 可以向其中注册内容，但没有消费端读取。必须建立消费端绑定：

RegistryConsumer绑定方式
ServiceRegistry FastAPI 依赖注入 Extension 注册的 Service 在 Depends() 中可用。通过 resolve_service(name) 懒加载。
MiddlewareRegistry AppFactory.with_middlewares() 在中间件栈构建时从 Registry 读取并注入。
ContentTypeRegistry Content Model Builder 内容类型列表 = 内置 + Registry 内容。
ProviderRegistry Storage / Search / Email 工厂 Provider 工厂从 Registry 收集可用驱动。
CustomFieldRegistry field_type_registry.py 已有 _PLUGIN_FIELD_TYPES dict 和 register_custom_content_model_field_type() 函数，直接对接。
AdminSlotRegistry Admin UI Slot Renderer 前端通过 API 获取已注册的 Slot 列表，动态渲染。

1.7 安全沙箱

安全层级措施
Permission 声明 Extension 在 manifest 中声明所需权限（content:read, workspace:settings 等）。加载时校验。
API 调用审计 Extension 所有 API 调用记录到 extension_audit_log 表。
错误隔离 单个 Extension 的异常不影响其他 Extension 和应用主体。加载失败 Extension 被标记为 error 状态。
资源限制 Extension 可使用的数据库连接数、内存上限、执行超时（Taskiq 任务级）。
网络限制 Extension 出站请求白名单（通过 manifest 声明外部域名）。

1.8 Extensions 数据库 Schema

-- 平台级：已安装的 Extension
CREATE TABLE extensions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) UNIQUE NOT NULL,       -- 标识符: "arclayer-ai-agent"
    display_name VARCHAR(255),               -- 显示名: "AI Agent"
    version VARCHAR(50) NOT NULL,            -- SemVer: "1.0.0"
    manifest JSONB NOT NULL,                 -- 完整 extension.json 内容
    source_type VARCHAR(20) DEFAULT 'local', -- "npm" | "git" | "local" | "registry"
    source_url VARCHAR(500),                 -- npm 包名 / git 仓库 / 本地路径
    status VARCHAR(20) DEFAULT 'installed',  -- "installed" | "error" | "upgrading"
    error_message TEXT,                      -- 上次加载失败原因
    installed_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 工作空间级：激活状态 & 独立配置
CREATE TABLE workspace_extensions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID NOT NULL,
    extension_id UUID NOT NULL REFERENCES extensions(id) ON DELETE CASCADE,
    enabled BOOLEAN DEFAULT TRUE,
    config JSONB DEFAULT '{}',               -- 工作空间级覆盖配置
    is_required BOOLEAN DEFAULT FALSE,       -- 平台强制启用（不可被 Workspace 停用）
    activated_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(workspace_id, extension_id)
);

-- Extension API 调用审计日志
CREATE TABLE extension_audit_log (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id UUID NOT NULL,
    extension_id UUID REFERENCES extensions(id),
    action VARCHAR(100) NOT NULL,            -- "api_call" | "db_query" | "http_request"
    resource VARCHAR(255),                   -- 调用的资源路径
    status VARCHAR(20),                      -- "success" | "error"
    duration_ms INT,
    details JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 索引
CREATE INDEX idx_workspace_extensions_ws ON workspace_extensions(workspace_id, enabled);
CREATE INDEX idx_extensions_name ON extensions(name);
CREATE INDEX idx_extension_audit_ws ON extension_audit_log(workspace_id, created_at);

1.9 迁移策略

2. AI 基础设施

2.1 src/llm/ 模块

定位零 FastAPI 依赖的纯 Python LLM 基础能力层。可被 src/modules/agents/、Taskiq 任务、Event Bus 订阅者、其他 Extension 等任何消费者调用。
不做什么不处理 HTTP 路由、不处理认证/授权、不处理多租户上下文（租户信息由调用方传入）。

模块结构

客户端封装

# src/llm/litellm_client.py
import httpx
from typing import AsyncIterator

class LiteLLMClient:
    """LiteLLM Proxy 的 Python 客户端封装

    使用 OpenAI 兼容接口格式（/chat/completions, /embeddings）。
    Virtual Key 解析器根据租户上下文选择正确的 API Key。
    """

    def __init__(self, base_url: str, settings: AISettings):
        self.base_url = base_url
        self.settings = settings
        self._client = httpx.AsyncClient(timeout=settings.request_timeout)

    async def chat(
        self,
        messages: list[dict],
        model: str | None = None,
        virtual_key_id: str | None = None,
        stream: bool = False,
        **kwargs
    ) -> dict:
        """发送 Chat Completion 请求"""
        headers = self._build_headers(virtual_key_id)
        payload = {
            "model": model or self.settings.default_model,
            "messages": messages,
            "stream": stream,
            **kwargs
        }
        response = await self._client.post(
            f"{self.base_url}/chat/completions",
            json=payload,
            headers=headers
        )
        response.raise_for_status()
        return response.json()

    async def chat_stream(
        self, messages, model=None, virtual_key_id=None, **kwargs
    ) -> AsyncIterator[dict]:
        """流式 Chat Completion"""
        ...

    async def embed(self, texts: list[str], model=None, virtual_key_id=None) -> list[list[float]]:
        """生成 Embeddings"""
        ...

    def _build_headers(self, virtual_key_id: str | None) -> dict:

Key 解析层级

class VirtualKeyResolver:
    """解析当前请求应使用的 LiteLLM Virtual Key。

    优先级（由高到低）：
      1. 用户配置了自有 LLM API Key → virtual_key: user/{user_id}
      2. 工作空间配置了独立 Key → virtual_key: workspace/{workspace_id}
      3. 回退到平台共享 Key → virtual_key: platform/shared
    """

    async def resolve(
        self,
        user_id: UUID | None = None,
        workspace_id: UUID | None = None
    ) -> tuple[str, str]:  # (virtual_key_id, virtual_key_name)
        # 1. 检查用户级 Key
        if user_id:
            user_key = await self._get_user_api_key(user_id)
            if user_key:
                return (f"user/{user_id}", user_key.name)

        # 2. 检查工作空间级 Key
        if workspace_id:
            ws_key = await self._get_workspace_api_key(workspace_id)
            if ws_key:
                return (f"workspace/{workspace_id}", ws_key.name)

        # 3. 平台共享 Key
        return ("platform/shared", "Platform Default")

# LiteLLM 中的 Virtual Key 结构
# Platform Master Key
#   ├── Virtual Key: platform/shared
#   │   ├── Budget: $1000/month
#   │   ├── Rate Limit: 1000 req/min

3.1 概述

定位src/modules/agents/ 是 API 感知的 Agent 层，依赖 src/llm/ 提供基础 LLM 能力。提供 REST API 端点、Agent 运行时（ReAct 循环）、工具系统（MCP + PydanticAI）、会话管理。

ReAct 循环

# src/modules/agents/runtime/engine.py
class AgentRunEngine:
    """Agent 运行时引擎 — ReAct (Reasoning + Acting) 循环

    ┌──────────────────────────────────────────────┐
    │                 ReAct Loop                    │
    │                                               │
    │  ┌─────────┐     ┌──────────┐     ┌────────┐ │
    │  │  THINK  │────→│   ACT    │────→│OBSERVE │ │
    │  │ (LLM)   │     │(Tool Use)│     │(Result)│ │
    │  └─────────┘     └──────────┘     └────────┘ │
    │       ↑                                  │   │
    │       └──────────── repeat ──────────────┘   │
    │                                               │
    │  Exit conditions:                             │
    │    - Agent 返回 final_response                 │
    │    - 达到 max_iterations (默认 15)              │
    │    - 累计 cost 超过 budget                     │
    │    - 用户手动取消                              │
    └──────────────────────────────────────────────┘
    """

    def __init__(
        self,
        llm_client: LiteLLMClient,
        tool_registry: ToolRegistry,
        session_manager: AgentSessionManager,
        settings: AISettings,
    ): ...

    async def run(
        self,
        user_input: str,
        context: AgentContext,        # workspace_id, user_id, permissions
        tools: list[str] | None = None,  # 限定的工具集
        max_iterations: int = 15,
        budget_cents: int | None = None,
    ) -> AgentRunResult:
        """执行 Agent 运行"""

        session = await self.session_manager.create(context, user_input)

        # 构建初始消息
        messages = [
            {"role": "system", "content": self._build_system_prompt(context, tools)},
            {"role": "user", "content": user_input}
        ]

        for iteration in range(max_iterations):
            # [THINK] 调用 LLM
            response = await self.llm_client.chat(
                messages=messages,
                virtual_key_id=context.virtual_key_id,
                tools=self.tool_registry.to_openai_format(tools),
            )

            # 记录审计日志
            await self._audit(response, context)

            # 检查预算
            self._check_budget(session, budget_cents)

            # 检查是否有 tool_calls
            choice = response["choices"][0]
            if choice["finish_reason"] == "stop":
                # [FINAL] Agent 完成
                session.final_response = choice["message"]["content"]
                await self.session_manager.complete(session)
                return AgentRunResult(
                    output=session.final_response,
                    iterations=iteration + 1,
                    tool_calls=session.tool_calls,
                    cost=session.total_cost,
                )

            # [ACT] 执行工具调用
            tool_results = []
            for tool_call in choice["message"].get("tool_calls", []):
                result = await self.tool_executor.execute(
                    tool_call, context
                )
                tool_results.append(result)

            # [OBSERVE] 将结果加入消息
            messages.append(choice["message"])
            for result in tool_results:
                messages.append({
                    "role": "tool",
                    "tool_call_id": result.call_id,
                    "content": result.content,
                })

            session.add_iteration(choice, tool_results)

        # 达到最大迭代次数
        raise MaxIterationsExceededError(
            f"Agent reached max iterations ({max_iterations})"
        )

MCP 格式定义

# src/modules/agents/tools/registry.py
class ToolRegistry:
    """工具注册表 — 用 MCP 格式存储工具描述，PydanticAI 执行"""

    def __init__(self):
        self._tools: dict[str, ToolDefinition] = {}

    def register(self, tool: ToolDefinition) -> None:
        """注册工具"""
        self._tools[tool.name] = tool

    def get(self, name: str) -> ToolDefinition | None:
        return self._tools.get(name)

    def list_all(self) -> list[ToolDefinition]:
        return list(self._tools.values())

    def to_openai_format(self, names: list[str] | None = None) -> list[dict]:
        """将工具转换为 OpenAI Function Calling 格式"""
        tools = [self._tools[n] for n in names] if names else self.list_all()
        return [
            {
                "type": "function",
                "function": {
                    "name": t.name,
                    "description": t.description,
                    "parameters": t.input_schema,
                }
            }
            for t in tools
        ]

@dataclass
class ToolDefinition:
    """MCP 格式的工具定义"""
    name: str
    description: str
    input_schema: dict        # JSON Schema
    handler: Callable          # PydanticAI @tool 装饰的函数
    permissions: list[str]     # 所需权限
    is_destructive: bool = False  # 是否为破坏性操作（写/删）

附录 A1. 术语表

术语定义
Extension扩展 Arclayer 功能的可安装包。包含后端（Python）和前端（React）代码。通过 Extension Manager 管理生命周期。
IntegrationExtension 的一种，专门连接外部服务（AI Provider、第三方 API、存储后端等）。
ConnectorExtension 的一种，专门实现数据导入/导出或与其他 CMS 同步。
ManifestExtension 根目录的 extension.json 文件。声明式元信息清单，不需要加载代码即可读取。
Registry类型化的子注册表。Extension 通过 Hook 向 Registry 注册资源（Service、Middleware、ContentType 等）。消费端从 Registry 读取。
LiteLLM ProxyOpenAI 兼容的 LLM 代理服务。作为 sidecar 运行，统一管理 100+ Provider 的路由、虚拟 Key、速率限制和成本追踪。
Virtual KeyLiteLLM 中的虚拟 API Key。支持层级化管理（Platform → Workspace → User），各自有独立的预算、速率限制和模型访问控制。
ReAct LoopReasoning + Acting 循环。Agent 的运行时模型：Think（分析）→ Act（调用工具）→ Observe（观察结果）→ 循环，直到任务完成或达到上限。
PydanticAI基于 Pydantic 的 AI Agent 框架。提供类型安全的输入/输出、依赖注入、内置测试支持。用于实现单任务 Agent。
LangGraph基于有向图的多步 Agent 工作流框架。提供 PostgreSQL Checkpoint、人工审批门、子图组合。用于复杂多步 Agent 管线（按需引入）。
MCPModel Context Protocol。标准化的工具描述格式，使工具定义可跨 Agent 框架复用。本项目用 MCP 格式描述工具，用 PydanticAI 执行。
LlamaIndex数据驱动的 RAG 框架。用于内容语义搜索、文档摄取、分块策略、混合检索（BM25 + Vector）。原生支持 pgvector。
LangfuseLLM 可观测性平台。用于追踪 LLM 调用链、管理 Prompt 版本、评估 Agent 输出质量。按需引入。
Admin SlotAdmin UI 中预定义的组件注入位置（Sidebar、Editor Toolbar、Content Actions 等）。Extension 可注册 React 组件到指定 Slot。
