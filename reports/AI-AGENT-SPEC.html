1.4 TenantAwareExtensionMiddlewareDispatcher v2.1 关键新增

审计 Critical 修复：Extension 中间件不能任意注入全局栈。 TenantAwareExtensionMiddlewareDispatcher 是第一方 ASGI 中间件，放在 auth/租户解析之后、Extension 安全请求阶段之前。Extension 注册的 hooks 通过它分发，Extension 代码永远不会看到未激活 Workspace 的请求。 
# 中间件栈顺序 (AppFactory 构建)
1. ArclayerSecurityMiddleware (Guard — CORS, rate limit, IP ban, CSRF)
2. GZipMiddleware
3. TrustedHostMiddleware
4. HTTPSRedirectMiddleware
5. LocaleMiddleware
6. RequestLogMiddleware
7. CorrelationIdMiddleware
8. AuthMiddleware (写入 request.state.workspace_id, request.state.user_id)
9. TenantAwareExtensionMiddlewareDispatcher   ← Extension hooks 在此之后
10. Extension Route Handlers

# Dispatcher 行为
class TenantAwareExtensionMiddlewareDispatcher:
    """仅将请求分发给当前 workspace 已激活的 Extension hooks"""

    async def __call__(self, request, call_next):
        ws_id = request.state.workspace_id  # 已由 Auth 中间件设置
        hooks = self.registry.get_active_hooks(ws_id, hook_type="request")
        for hook in hooks:
            request = await hook.before_route(request)  # hooks 不可修改 auth 上下文
        response = await call_next(request)
        for hook in reversed(hooks):
            response = await hook.after_response(request, response)
        return response

# Extension 可注册的 hook 类型 (Phase 2 仅支持这些)
# - before_route(request) → request
# - after_response(request, response) → response

class LLMRuntime:
    """LLM 调用唯一入口。调用方不需要传递 virtual_key_id、不需要自行审计。"""
    async def chat(self, messages, context: LLMRequestContext) -> ChatResult:

        # 2. Model Policy 校验 (允许模型/最大 token/成本上限/provider 限制)
        # 3. 预算预检查 & 原子预留 (见 §2.4)
        # 4. 调用 LiteLLM

@dataclass
class LLMRequestContext:
    workspace_id: UUID
    user_id: UUID | None
    correlation_id: str
    source: Literal["agent", "event", "api"]

2.2 LiteLLM Proxy

Sidecar 部署。Master Key 仅用于 Key 管理，推理请求使用 Virtual Key 作为 Bearer auth。Arclayer 层追加熔断策略：

  • LiteLLM 不可用 → 503 + "AI service temporarily unavailable"
  • Provider 不可用 → LiteLLM fallback (按配置) → 成功则审计标注 fallback
  • Model 不可用 → 400 + 明确错误码
  • 速率限制 → 429 + retry-after
  • 流式中断 → 已输出内容保留、实际 usage 对账

2.3 Key 模型 v2.1 完善

Workspace-First 解析 + Grant 授权生命周期

Key 解析:
  1. Workspace 拥有独立 Key → workspace/{id}
  2. Workspace 未配置, 但用户已授权个人 Key 到此 Workspace → user/{uid}:ws/{wid}
  3. 以上均不满足, Workspace 允许使用平台共享 Key → platform/shared

Grant 生命周期约束:
  - user_key_workspace_grants 创建时校验:
    用户是 Workspace 成员 AND Workspace admin 批准 OR 用户有 bring_own_key 权限
  - 用户退出 Workspace → 自动撤销所有 grant
  - Key 轮换/撤销 → cascade disable 关联 grant
  - Agent/后台任务在每次调用前检查 grant 是否仍有效
  - LiteLLM Virtual Key metadata 携带 {workspace_id, owner_user_id, grant_id}

2.4 预算账本 v2.1 关键新增

原子预算预留 — 防并发超额

-- 预算表 (per funding source)
CREATE TABLE ai_budgets (
    id UUID PRIMARY KEY,
    source_type VARCHAR(20) NOT NULL,    -- "workspace" | "user" | "platform"
    source_id UUID NOT NULL,
    limit_cents BIGINT NOT NULL,         -- 月度上限 (美分)
    spent_cents BIGINT DEFAULT 0,       -- 已确认花费
    reserved_cents BIGINT DEFAULT 0,    -- 当前预留额
    period_start DATE NOT NULL,
    UNIQUE(source_type, source_id, period_start)
);

-- 预留账本 (每笔 LLM 调用的临时预留)
CREATE TABLE ai_budget_reservations (
    id UUID PRIMARY KEY,
    budget_id UUID NOT NULL REFERENCES ai_budgets(id),
    request_id UUID UNIQUE NOT NULL,     -- correlation_id / LiteLLM request_id
    estimated_cost BIGINT NOT NULL,      -- 预估花费 (微美元)
    reserved_cost BIGINT NOT NULL,       -- 实际预留额
    actual_cost BIGINT,                  -- 对账后实际花费
    status VARCHAR(20) DEFAULT 'reserved', -- reserved|committed|released|expired
    expires_at TIMESTAMPTZ NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 原子预留操作
UPDATE ai_budgets
SET reserved_cents = reserved_cents + :reserve_amount
WHERE id = :budget_id
  AND limit_cents - spent_cents - reserved_cents >= :reserve_amount
RETURNING id;  -- 返回 0 行 = 预算不足

-- 对账操作 (LiteLLM 返回实际 usage 后)
UPDATE ai_budget_reservations SET status='committed', actual_cost=:actual;
UPDATE ai_budgets SET reserved_cents = reserved_cents - :reserved + :actual,
                     spent_cents = spent_cents + :actual;

-- 过期预留回收 (定时任务)
UPDATE ai_budgets SET reserved_cents = reserved_cents - r.reserved_cost
FROM ai_budget_reservations r
WHERE r.status = 'reserved' AND r.expires_at < NOW()
RETURNING r.id;  -- 同时更新这些 reservation 为 expired

3.4 审批门 v2.1 完善

审批流程:
  Agent 决定写操作 → Dry-Run (绑定 content/schema version)
  → 用户 Approve/Reject/Modify
  → 执行时重验: 版本一致? 权限仍有效? 审批未过期? 参数与审批一致? 防重放?
  → 写入审计 (审批 ID + correlation ID)

审批策略:
  always_approve:      所有写操作需审批 (Phase 3B 默认)
  approve_bulk_only:   >5 条批量需审批
  approve_schema_only: 仅 Schema 变更需审批
  auto_approved:       白名单自动化 Agent (Phase 4)

3.5 SSE 流式契约 v2.1 新增

SSE 事件类型:
  session.started    { session_id, agent }
  message.delta      { content: "..." }
  tool.started       { tool_name, args }
  tool.completed     { tool_name, result_summary }
  approval.required  { approval_id, tool_name, dry_run_diff }
  usage.partial      { prompt_tokens, completion_tokens, cost_micros }
  message.completed  { full_content }
  session.completed  { session_id, total_cost, iterations }
  session.failed     { error_code, message }
  session.cancelled  { session_id }
  heartbeat          {}  (每 30s)

行为:
  - 不支持 reconnect (断连后 Client 重新 GET /sessions/{id} 恢复状态)
  - 断连自动触发 cancel 流程 (释放预算预留)
  - auth 过期 → session.failed with AUTH_EXPIRED
  - 流式中断时已输出内容持久化到 session.messages
  - 预算对账使用实际 delivered tokens
