# Use risk-tiered domain-owned configuration

Platform Console configuration remains in its owning Platform Domain and uses risk-tiered mutations rather than autosave, a universal Draft-and-Publish workflow, or a global Settings area. Every surface separates effective value or sanitized state, source authority, readiness, missing prerequisites, affected scope, last successful change, and health; low-risk settings require an explicit server-confirmed save, while high-risk or cross-Workspace changes require a revision-bound impact preview and separate apply confirmation. Credentials are write-only replacements with independent connection testing, asynchronous acceptance remains pending until the durable result commits, stale or partial outcomes stay visible, and every applied change produces canonical Audit evidence and plain-language result copy.
